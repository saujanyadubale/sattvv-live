05 / WHAT THE METHODS DO

Five decisions in a closed loop

Detect

Thresholds, trends, CUSUM, physical-model residuals and ML anomaly detectors indicate abnormal observations.

Predict

Persistence, physics extrapolation, linear trend and gradient boosting forecast telemetry over 2–10 simulated minutes.

Diagnose

Update fault hypotheses from the evidence obtained by executed tests. Hypothesis weights remain uncalibrated.

Verify

Choose and run a procedure. Only an executed check can verify a requirement failure—not a forecast alone.

Audit

Recalculate supported numerical pass/fail checks and verify policy labels, observation timestamps and trace consistency.

Boundary

Internal evidence consistency is not independent flight validation or proof of the fault root cause.

Research question

Does using warnings, predictions and fault uncertainty to choose verification procedures improve detection time and test cost versus static or simpler adaptive strategies? The latest synthetic pilot is mixed: no consistently dominant policy.

06 / ACTUAL IMPLEMENTATION — METHODS & MODELS

Which algorithms are inside SAT-V&V?

Our platform combines physics, classical statistics, trained ML and manually designed decision policies. They perform different jobs: warning, forecasting, diagnosis or deciding which test to run next. The following is based on the working Python source, not proposed future features.

DETECTION · UNSUPERVISED ML

Isolation Forest

Trained on healthy synthetic telemetry features: voltage residual, current, temperature, packet loss, sensor disagreement, charge, load, solar power and operating mode. Isolation Forest gives unusual observations higher anomaly scores. Its warning threshold is tuned on separate healthy campaigns.

Architecture, settings and limitations

80 trees · contamination='auto' · seed=71. Does not require labeled faults for fitting, but can miss faults that resemble nominal variation. It flags anomalies, not fault causes.

DETECTION · SUPERVISED ML

Gradient-Boosted Classifier

Histogram-based boosted trees distinguish synthetic active-fault telemetry from healthy records. Features use only current and past measurements. The output is a fault-monitoring score, not a detailed causal diagnosis.

Architecture, settings and limitations

80 boosting iterations · max 12 leaf nodes · learning rate .08 · min 18 samples per leaf. Training faults share model assumptions with evaluation faults; performance may degrade under unfamiliar physics.

PREDICTION · ML + BASELINES

Voltage & Temperature Forecasters

Compare persistence, physical extrapolation, local linear trends and a histogram gradient-boosting regressor predicting voltage/temperature 2, 5 or 10 simulated minutes ahead. Calibration uses separate synthetic campaigns.

Architecture, uncertainty and limitations

75 iterations · 13 max leaf nodes · learning rate .055 · L2 .10. Constant-width bands use a split-conformal-style rank of worst errors per calibration campaign (nominal 90%). Under distribution shift, coverage is not guaranteed. A predicted crossing is a warning, never an automatic FAIL.

TEST SELECTION · SUPERVISED ML

Random Forest Test Ranker

Trained offline to estimate which verification procedure is most likely to expose a requirement failure. Inputs include test ID, duration, criticality, telemetry, mode, remaining test history, repeats and nominal-voltage residual.

Architecture, objective and limitations

80 trees · depth 8 · min 3 samples/leaf · seed=2026. The training target is whether an executed test failed in synthetic training data. It is not a root-cause detector. Including test ID may produce catalog-specific learned shortcuts; predicted scores are uncalibrated.

DIAGNOSIS · PROBABILISTIC MODEL

Bayesian Fault Hypotheses

Maintains weights for battery, thermal-sensor, heater, communications and attitude-control fault hypotheses, plus healthy. Each completed requirement PASS/FAIL updates the weights using an explicitly defined likelihood table.

What is learned—and what is not?

Requirement-specific signatures in diagnosis_v096.py are expert-assigned, not trained fault probabilities. The updates approximate conditional independence; repeated and correlated observations can inflate confidence. The system does not yet reliably recover multiple causes.

SCHEDULING · HEURISTIC + INFORMATION THEORY

Five Verification Strategies

Fixed follows the catalog. Temporal adaptive weighs coverage, age, warning and cost. Information gain uses expected Bayesian entropy reduction. ML-ranked adds Random Forest failure-likelihood scores. Predictive active combines forecast risk, information gain, coverage, repeats and safety guards.

Which one is our proposed method?

Predictive active is our experimental integration, not a reinforcement-learning policy. It is not consistently better than the baselines in synthetic benchmarks. All strategies execute real modeled test procedures; they do not automatically infer hardware root cause.

CLASSICAL SIGNAL PROCESSING

Thresholds, OLS Trend, CUSUM & Physics Residual

Thresholds detect limit violations. Rolling least-squares trend uses a 180-second history of residuals. CUSUM accumulates persistent positive residual deviation. Physics residual compares measured voltage with a simplified expected value from battery charge and load.

Where these fail

Manually tuned thresholds and imperfect physical models can produce missed warnings or false alerts. A warning is not a formal verification FAIL.

VERIFICATION · NOT ML

Physical Simulation & Evidence Audit

Coupled electrical/thermal dynamics, mode guards and single-axis ADCS determine the simulated response. Twenty project-defined procedures produce actual recorded requirement checks. Deterministic auditors verify supported numerical limits, timestamps and decision provenance.

What remains unvalidated?

These are illustrative dynamics, not flight-calibrated component models. Audit consistency proves only that recorded evidence supports internal PASS/FAIL logic, not that the physical model matches flight hardware.
