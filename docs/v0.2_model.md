# v0.2 — Dynamic Spacecraft Emulator: Model, Assumptions, and Research Integrity

## Design principle

A **simulation**, not a physically validated digital twin. Its purpose is to introduce nontrivial time evolution, engineering coupling, commands and feedback without claiming real CubeSat fidelity. All adjustable parameters are **illustrative**. Spacecraft fault identity and severity stay in the evaluation harness, not in the telemetry. Exported scenario JSON contains fault metadata for ground-truth annotation, but telemetry samples do not.

## Discrete state and operating modes

Legal transitions: BOOT→SAFE; SAFE→NOMINAL; NOMINAL→{SAFE,PAYLOAD}; PAYLOAD→{NOMINAL,SAFE,DOWNLINK}; DOWNLINK→{PAYLOAD,SAFE}. Rejected illegal transitions produce a command acknowledgment with `reason=ILLEGAL_TRANSITION`. We inject an explicit SAFE→DOWNLINK probe; the illegal-transition fault accepts this edge and emits an event. Mode loads (watts) are illustrative: BOOT 2.3, SAFE 1.8, NOMINAL 3.8, PAYLOAD 6.4, DOWNLINK 5.6.

## Electrical power state

Define battery capacity \(E=24\ \mathrm{Wh}\), state of charge \(q\in[0,1]\), electrical load \(P_L\) in watts and sunlight generation \(P_S\) in watts. For a fixed timestep \(\Delta t\) in seconds:

\[
q_{k+1}=\mathrm{clip}_{[0,1]}\left(q_k+\frac{(\eta P_S-P_L)\Delta t}{3600 E}\right)
\]

Default \(P_S=8\ \mathrm W\) when illuminated, zero in eclipse; charge efficiency \(\eta=0.9\). Reported bus voltage uses an illustrative SOC and load proxy:

\[
V=6.55+1.60q-0.045P_L-V_{\mathrm{fault}},\qquad I=P_L/\max(V,0.5)
\]

The undervoltage fault introduces severity-scaled drop \(V_{\mathrm{fault}}=s(0.25+0.11P_L)\). The overcurrent fault adds \(5.2s\) watts to load. **This is not an equivalent-circuit battery model**; coefficients are chosen for easily interpretable toy demonstrations.

## Thermal state

Single-node heat balance:

\[
C\frac{dT}{dt}=\alpha P_L+P_{\mathrm{fault}}-k(T-T_a)
\]

Default \(C=260\ \mathrm{J/K}\), \(k=0.075\ \mathrm{W/K}\), \(\alpha=0.72\), \(T_a=18^\circ\mathrm C\). We integrate analytically over each timestep at constant load:

\[
T_{k+1}=T_a+(T_k-T_a)e^{-k\Delta t/C} +\frac{\alpha P_L+P_{\mathrm{fault}}}{k}(1-e^{-k\Delta t/C}).
\]

The thermal runaway fault adds \(13s\ \mathrm W\) of sustained heating. Two temperature sensors get independent Gaussian observation noise (\(\sigma=0.10^\circ\mathrm C\)), except a stuck redundant sensor holds its first post-fault reading. **Fixed noise levels and a constant thermal environment are deliberately unrealistic.**

## Housekeeping and fault evidence

Visible alarm limits: \(V<6.70\ \mathrm V\), \(I>1.30\ \mathrm A\), \(T>70^\circ\mathrm C\), temperature sensor separation >3 °C; downlink loss >0.10, telemetry latency >250 ms, checksum failure; watchdog timeout after 120 s of unresponsive CPU. A watchdog probe is injected at simulation t=1500 s in both healthy/faulty cases. A working watchdog restarts to SAFE after 120 s; a failed watchdog does not. Command acknowledgments explicitly show payload-enable failure. Healthy scenario's deliberately illegal SAFE→DOWNLINK command must produce a rejection; this is expected and not an alarm.

Bus voltage / temperature may trigger an automatic SAFE transition using simulated physical truth. The project makes no safety guarantee for real spacecraft.

**Telemetry schema** (a single row):

`time_s, mode, battery_soc_pct, bus_voltage_v, bus_current_a, load_w, solar_w, temperature_c, redundant_temperature_c, packet_loss_fraction, latency_ms, checksum_ok, cpu_responsive, alarms`

Ground-truth annotations (`fault`, `severity`, `fault_start_s`) are in the experiment's `meta` field only. Command/event stream uses `time_s`, `type`, and type-dependent ACK / cause fields. A later protocol layer will introduce schema versioning and communication faults applied to the entire telemetry transport; today some faults affect link-health telemetry fields but not the reliable in-process UI data channel.

## Schedule, sampling, and evidence

For all documented web scenarios, input parameters have equal defaults (initial SOC 80%, 30 s timestep, 50 min duration, fault onset t=600 s, seed 7). The command script cycles SAFE, NOMINAL, PAYLOAD, DOWNLINK and repeats, including a deliberate illegal guard probe. Commands and fault onsets must align to sample boundaries. The dashboard returns **exactly one trajectory** per click, not a benchmark mean. `first_alarm_s` is the first violated threshold; `first_evidence_s` is the earlier of that or explicit `guard_violation` / `payload_enable_failure` events. Both are synthetic labels, not externally validated detection rates.

## Quality checks and next ablations

- Dimensional check of SOC energy integration in Wh and hours.
- Legal transitions and one corrupt guard; payload boot failure.
- Healthy false-alarm and watchdog recovery control; faulty watchdog nonrecovery.
- Increased charging under sunlit conditions relative to eclipse.
- Thermally inertial behavior; every fault must produce some observable anomaly at default severity and horizon.
- Repeatability with fixed seeds and absence of hidden fault IDs in telemetry.
- Original v0.1 unit tests preserved, its results unchanged.

Remaining: physics-informed or mission-data calibration; thermal/electrical parameter sweeps; timestep convergence check; independent property-based tests; delayed/noisy/packetized telemetry, battery bounds under low SOC; realistic orbital illumination; start-time disturbances; validate detector false alarms; integrate policies and compare to model-fixed on genuinely unknown fault trajectories.

## UI / eventual hosted portfolio design

The interactive `web/index.html` is intentionally thin. POST to `localhost` API `/api/simulate`; get same JSON used by CLI; plot voltage, battery, temperature, current and list events. Future website will provide 4-policy comparison, protocol-aware test replay, a requirement/test/evidence matrix, fault-onset timeline, reproducible shareable scenario configs, exportable report, and hosted backend. A static website by itself cannot run this Python engine: host the API too, or precompute scenarios / port the model deliberately.
