# SAT-V&V v0.9.4 — Diagnostic and Evidence Validation

## Objective and scope

v0.9.4 addresses two observed issues: the potential disagreement between the strategy selected on screen and a strategy label in exported trace data; and the lack of readable measured values and limits supporting PASS/FAIL outcomes. It evaluates whether the ML-ranked strategy's advantage in one successful example persists across other synthetic conditions. No flight validation is claimed.

## What changed

1. **Policy provenance:** a single policy key flows from browser settings through the API, campaign metadata, and each decision record. The backend audit checks consistency of all records, the policy-specific reason, and the decision observation timestamp. Browser rendering rejects mismatches. Displayed run settings come from the response metadata, not from settings subsequently changed in the page. The comparison browser freezes scenario inputs at launch. Changing experiment settings hides stale result panels.
2. **Numeric evidence:** T13–T16 now record human-readable metrics, observed values, applicable numerical limits and measurement units. T14's high-load model residual and voltage recovery error are derived from exactly the same observations and expressions used to decide PASS/FAIL. For existing tests T01–T12, measured extrema are supplied when available. An independent code path recomputes numeric bound outcomes from these stored metrics. Other checks remain explicitly boolean, rather than having made-up numeric evidence.
3. **Causal time:** each decision stores the telemetry observation time and it must match the test start time. This does not independently prove that forecasting-model training was causally separated; that is a separate model-validation question.
4. **Readable result view:** the web page displays failing requirements with numeric margins; JSON is available under an advanced expandable section.
5. **Benchmark:** paired seeds, identical starting configurations per test policy, two time budgets, single-fault and compound-fault synthetic campaigns, healthy controls, timing and top-hypothesis agreement for single-fault families. No favorable-seed selection.

## Falsification tests

- Change one trace record's `selected_policy` to another strategy: provenance audit must fail.
- Change the policy-specific decision rationale: audit must fail.
- Change a recorded observed value while leaving check result unchanged: numerical audit must fail.
- Change observation timestamp after a test has completed: causal timestamp audit must fail.
- Repeat a scenario/seed: exact trace must be reproducible.
- Predicted risk without an executed failed test must never count as formal FAIL.

## Simulation and benchmark

`python -m satvv bench-audit --seeds 3` evaluates 5 policies, 8 scenario families, 3 seeds/family, and 20- and 26-minute budgets (240 total campaigns). Faults begin at minute 5. Six scenario families are faulty (18 campaigns per method/budget), two are healthy (6 campaigns per method/budget). The four single-fault families are `resistance_ramp`, `intermittent_resistance`, `sensor_drift` and `heater_fault`. Two compound families are `dual_resistance_sensor` and `wheel_plus_battery`. Healthy controls are `healthy` and `normal_load_cycle`.

The model-fitting seeds differ from the scenario evaluation seeds, but the training examples use the same synthetic physics and some of the same fault families. This is **not** independent external validation. The learned ranker includes test ID and test criticality as features and may learn the synthetic catalog's test-specific failure frequencies. This is a known limitation, not a discovered causal law.

### Reporting rules

- Primary: failed requirement check in a faulty campaign before the budget expires.
- Safety/control: failed requirement check in a healthy campaign.
- Diagnosis: top-hypothesis match on known single-fault campaigns only (uncalibrated weights, not confirmed causes).
- Detection delay: `detection time - injected onset`; reported only for detected campaigns to avoid misinterpreting censored misses as zero delay.
- Paired comparison: same scenario/seed/onset/budget for all policies; the actual spacecraft trajectories diverge when policies select different tests.
- Small sample sizes and clustered scenario families mean that pilot rates should **not** be treated as statistically significant superiority.

## Invariants and caveats

- `audit_trace` validates internal evidence consistency, NOT authenticity of external measurements, physical-model realism, cross-sensor provenance, or the correct fault root cause. Numerical metrics are still produced by the simulator under test. Raw JSON is optional for scientific inspection but never used as the main browser explanation.
- The older `core.REQUIREMENTS` table applies to the v0.1 toy emulator and retains a 2.60 A EPS current limit. The v0.2+ dynamic simulation requires **1.30 A** for the same legacy identifier. The browser uses the v0.9.4 dynamic check limit; the two historical specifications must not be confused in any formal traceability report.
- The forecaster's estimated probability bands and the Bayesian top-hypothesis weights remain uncalibrated for operational spacecraft.
- Some ADCS and communication checks still record categorical outcomes only. Future versions should add direct measurement-level provenance and validation for every requirement.
- The live browser may not be available in every container environment; `node --check web/lab.js` and the automated API/DOM tests complement, but do not replace, validation on your machine.
