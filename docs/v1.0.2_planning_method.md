# Risk-aware short-horizon planner — technical note

**Algorithm type:** non-learning, model-informed, deterministic bounded beam search. No reinforcement learning, no hidden injected-fault features, no numerical flight hardware inference.

**State at decision time:** latest measured spacecraft telemetry, current Bayesian hypothesis weights, requirements verified and their ages, past procedure counts, remaining simulated verification time, already applied safety guards, and observable subsystem/forecast warnings. These inputs are populated by `run_pipeline` before the candidate planner is called.

**Action space:** safely affordable procedures from the 20-test catalog. The planner never adds an unsafe excluded test back to the choice set. Test durations, requirement identifiers and subsystem associations come from the catalog.

**Heuristic predicted failure value:** for procedure `t`, each hypothesis `h` has project-specified failure signatures `P(FAIL_req | h)`. A procedure's approximate failure hazard is a weighted sum of `1 - product(1 - P(FAIL_req | h))`, marginalised over the current hypothesis weights. This is **not** a calibrated probability of real spacecraft failure.

**Search:** beam width 12, depth 3. Each candidate plan consists of distinct procedures whose total catalog costs do not exceed remaining time. The heuristic rewards early fault discovery, expected information gain, previously unchecked requirements, subsystem diversity, stale-check renewal, and observable subsystem risk. It penalizes repeated procedure and subsystem visits and longer test times. The beam optimizes a discounted heuristic score; its assumptions are more limited than actual model-predictive control because it does not propagate physical state through hypothetical tests. Deterministic ties resolve by catalog ID.

**Online execution:** only the **first** action from the selected plan is executed. After its measured outcome is recorded, the model updates the diagnostic weights, timestamps and telemetry, then replans. Actual PASS/FAIL comes only from the executed verification check. Planning scores cannot directly create FAIL results.

**Short budget:** original total budget <=35 minutes deliberately uses the v1.0.1 greedy/coverage-guard controller to avoid the short-window regression observed during development. This fallback is a **post-development design choice**, so earlier benchmark observations were used in choosing it; it is not proof of unbiased performance on those same cases.

**Audit:** decision records contain the policy label, the `scheduler_mode`, selected proposed test list, heuristic objective and count of candidate sequences. They must not contain injected ground-truth mechanism labels. The existing evidence auditors verify policy consistency, supported measurements, timestamps and test outcomes.

**Validation needed next:** independently generated faults/plant models, statistical confidence across many seeds, multi-cause diagnosis, calibrated risk estimates, parameter-ablation studies, larger healthy controls, and a pre-registered evaluation protocol.
