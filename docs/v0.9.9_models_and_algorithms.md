# SAT-V&V v0.9.9 — Models, Algorithms & Scientific Boundaries

The following descriptions refer to implemented code, not a proposed future architecture. All models currently operate on project-defined synthetic spacecraft telemetry. Numbers are not flight reliability claims.

## Physics and verification engine
- **Coupled spacecraft simulator** (`satvv/coupled.py`, `satvv/adcs_v08.py`): battery state-of-charge energy balance, voltage sag with internal resistance and electrical load, resistive heating and lumped thermal response, modes/guards, sampled communications and simplified single-axis ADCS. 10-second simulator steps. These are simplified illustrative dynamics, not calibrated hardware/flight digital twins.
- **Test execution** (`satvv/integrated_v08.py`, `satvv/verification_v05.py`): 20 test procedures spanning EPS, OBC, Thermal, COMMS, Payload and ADCS. Different policies can change future spacecraft state because executing a test changes mode, power and temperature. A **PASS** means an executed requirement passed, not that the spacecraft is fault-free.

## Detection: classical and ML methods
- **Limit tests:** directly check project-defined measurement limits or telemetry alarm flags. Strength: interpretable; weakness: may detect a problem only when a limit is crossed.
- **Rolling linear trend:** uses the past 180 seconds of physics-model voltage residuals, computes a least-squares slope, warns when it exceeds a hand-set value. Causal window; not an independently calibrated prognostics system.
- **CUSUM:** accumulates positive residual excess; detects persistence but needs meaningful baseline and threshold calibration.
- **Physics residual:** compare measured bus voltage to a simplified expected voltage from charge and electrical load; also check disagreement between temperature sensors. May false-alarm if physical assumptions differ from reality.
- **Isolation Forest** (`satvv/ml_benchmark.py`): scikit-learn `IsolationForest(n_estimators=80, contamination='auto', random_state=71)`. Fit on healthy synthetic feature vectors (voltage residual and slope, voltage, current, temperature, sensor disagreement, packet loss, charge, load, solar power and mode indicators). Calibrate anomaly-score cutoff on separate healthy synthetic campaigns. It is **unsupervised**, flags unusual patterns but does not identify a fault root cause.
- **Histogram Gradient Boosting Classifier** (`satvv/ml_benchmark.py`): `HistGradientBoostingClassifier(max_iter=80, max_leaf_nodes=12, learning_rate=.08, min_samples_leaf=18, random_state=71)` trained on labeled synthetic active-fault vs healthy telemetry. Produces an estimated fault-class score for monitoring; labels and fitted calibration still come from the same family of synthetic failure mechanisms. Not a multi-fault diagnostic classifier or flight-validated probability.

## Forecasting models
The v0.6 forecasting comparison (`satvv/forecast_v06.py`) includes **persistence**, **physics extrapolation**, **local linear trend**, and **Histogram Gradient Boosting Regressor**. Forecast targets are future bus voltage or temperature over 2-, 5- or 10-minute horizons. The regressor is `HistGradientBoostingRegressor(max_iter=75,max_leaf_nodes=13,min_samples_leaf=28,learning_rate=.055,l2_regularization=.10,random_state=47)`. Fitting and calibration use separate synthetic campaigns. Constant-width uncertainty bands are based on the maximum absolute forecast error per calibration campaign (a split-conformal-style procedure with a nominal 90% target). This does not guarantee correct coverage under operating-condition shift. Forecast warning **never** automatically establishes a requirement failure.

## Diagnosis and decision making
- **Requirement-level Bayesian hypothesis updater** (`satvv/diagnosis_v096.py`): each requirement has manually specified per-hypothesis failure likelihoods. Pass/fail evidence updates normalized posterior *weights*. Some PASS contributions are deliberately downweighted. This assumes independent checks and can be overconfident. A single-hypothesis model **cannot** identify every contributing cause in a compound fault. We explicitly label weights as **uncalibrated**.
- **Fixed-order baseline**: executes the test catalog in an established order with an available time budget. Does not use telemetry-driven reprioritization.
- **Temporal-adaptive heuristic**: re-scores tests using unverified requirements, age of prior evidence, criticality, warning signals, repetitions and duration. Manually designed weights, not ML.
- **Bayesian information-gain selector**: computes expected reduction of entropy in fault-hypothesis weights from possible PASS/FAIL evidence, and adds value for requirement coverage, freshness and criticality. The utility is heuristic; likelihoods and posterior weights are not calibrated for real hardware.
- **Random Forest learned test ranker** (`satvv/learned_v09.py`): `RandomForestClassifier(n_estimators=80,max_depth=8,min_samples_leaf=3,random_state=2026)` trained offline on simulated executions. Each feature vector includes **test ID**, test duration and criticality, current time, voltage/current/temperature, temperature-sensor difference, packet loss, SOC, mode, check age, repeat count and a nominal-voltage residual. Target: whether that candidate test revealed a failure in the training run. It predicts a test-failure *ranking score*, **not a root-cause diagnosis** and not a calibrated failure probability. Test ID can lead to learning catalog-specific patterns instead of general physics.
- **Predictive-active selector** (`satvv/pipeline_v093.py`): handcrafted score combines coverage, measurement freshness, test criticality, repeated-test penalties and subsystem warnings with expected Bayesian information gain plus forecasted voltage/thermal risks. Safety guards exclude some high-load tests when voltage/charge/forecast thresholds show elevated risk. Neither reinforcement learning nor end-to-end trained decision-making has been implemented.
- **Evidence audit** (`satvv/evidence_v094.py`): deterministic consistency checks of recorded tests, numerical limits where available, policy IDs and timestamps. This is NOT an ML model, not independent physics validation, and not proof of root cause.

## 3D mission visualization
`web/mission3d.js` is a dependency-free perspective 3D geometry renderer using HTML Canvas. It synchronizes spacecraft areas and a conceptual ground station with **recorded** test execution, outcome and posterior-weight evidence. Amber highlights represent uncalibrated suspicion, while red highlights represent the **subsystem tested by a failed check**—not proven root cause. Injected fault zones are drawn only when a user explicitly reveals hidden ground truth **after the run**. It is not a CAD model, orbital propagator, spacecraft localization system, live telemetry stream or live communication link.

## Validation requirements before publication
- Preserve test-by-test reproducibility, script/runtime integrity and honest reporting of no-detection cases.
- Benchmark independent fault generators and test catalogs as well as in-family synthetic scenarios.
- Report failed-check detection, fault identification, warning lead time, false alarms, coverage and verification cost *separately*.
- Report uncertainty intervals and deviations from calibration targets; use held-out campaigns and external datasets only for the tasks they actually support.
